Dark glass UI — dark-glass-ui

The homepage puts PDF upload first, with six compact sample EULAs below it.
The samples retain their original 164 categories, summaries and media.

Selecting a sample or opening an analyzed PDF from the upload queue opens the category gallery.
Sample and uploaded categories share a set of 24 illustrated objects. The
browser selects up to two from the extracted title as soon as analysis finishes.
Related titles can share a subject and show different accompanying objects.
Unfamiliar titles use their own initials on etched glass. Initials also keep
every tile usable while the shared image loads. The artwork stays stable as
videos and comics finish. The category grid scrolls beneath a fixed heading
and search box. Search matches the whole agreement and shows the number of matches.
Choose a category to open its review. Closing this first chooser returns home.
Browse categories reopens it on the current category. Closing it there returns
to the same reader and format. Reduced motion skips transitions.

The upload-capable public review is at https://api.eulalens.stream/review/.
The upload queue accepts multiple PDFs and shows each analysis independently.
Open becomes available when categories are ready. Comic and video counts update
while the reader browses other documents. Reload reconnects accepted jobs from
their local identifiers. PDF bytes and extracted text stay out of browser storage.
It serves the PDF reader locally and sends analysis requests to its own origin.
Switch EULA in the reader opens the PDF picker and sample choices. A canceled
picker or unreadable replacement leaves the current agreement available.
The shared GitHub file preview links to the public workspace for uploads.

The format order is Video, Comic, Cue cards and Original EULA. Video opens first. The header identifies the agreement, category
position and risk. Desktop has a risk-grouped category index; on smaller
screens the position control opens the category picker. Previous/Next and the
index retain the selected format. The player and navigation fit the viewport.
Long documents, scene text and lists scroll within their panels. In portrait,
the category notes sit beneath the video. Details opens them from other formats.
Impact and Lookouts are visible in both layouts.

Cue cards flip in place. The comic reader includes the selected scenario’s
summary. Scenes places the original dialogue, thoughts and captions over the
artwork. Full comic opens the entire sheet in the reader and supports zoom.
Select any panel on the sheet to open that scene. Demo agreements include
frame coordinates for every scene. Uploaded comics use the image gutters
when they match the script, then the layout requested from HiDream.

Comic opens paused. Read aloud starts on, and Play uses the displayed sound
preference. Changing the category or scenario leaves the next comic paused.
Muted comics advance on a reading timer.
Full comic highlights the current panel and follows it while zoomed. Switching
between Scenes and Full comic keeps the same playback position. Choosing a
different scene, opening a dialog or leaving Comic pauses playback.

All six sample agreements include original scenario metadata and a local MP3
per comic. The 164 recordings and 969 scene timings work on static hosting.
To rebuild them, use the Kokoro environment with its cached weights and voice,
NumPy and ffmpeg, and run tools/build_sample_narration.py. Use --device cuda for
an offline batch on a GPU. The builder reuses completed tracks on interrupted
runs, then writes sample-narration.js. Uploaded comics queue CPU narration when
their stories are available, alongside image rendering. Play reuses prepared
clips through the authenticated API (see model-services/README.txt).

ui.css provides the glass styling, ui.js handles view controls and
category-gallery.js builds the chooser from the current agreement. The shared
WebP at images/category-objects.webp contains six columns and four rows.
tools/category-art-prompt.txt records the prompt for the built-in ImageGen asset.
The existing API and scheduler handle uploads and media generation.

After editing a local browser script or ui.css, run node tools/version-ui.mjs.
It updates the asset URLs in index.html so returning browsers receive matching
scripts and styles. npm test checks those URLs against the file contents.

Verification (Node >=22.13; ffmpeg for the upload/media fixture test):
  npm ci
  npx playwright install chromium
  npm test
  npm run test:ui
  npm run test:browser

The browser suites use local fixtures or existing static samples and do not
submit inference jobs to the production model services. test:ui exercises all
six samples, 164 illustrated categories, desktop and phone layouts in both
orientations, keyboard upload, cue cards, asynchronous refreshes, both comic
views, audio playback, category navigation, video, PDF,
retry controls, dialogs, research and reduced motion. test:browser exercises
PDF extraction, authenticated API jobs, scenario switching, captions, source
evidence, restoration without duplicate generation and expired-session recovery.

Optional environment variables:
  EULALENS_SCREENSHOT_DIR      Destination for test:ui screenshots.
  EULALENS_PLAYWRIGHT_MODULE   ESM entry for an external Playwright installation.
  EULALENS_PDFJS_BUILD_DIR     Override the pinned local PDF.js test build.
  PLAYWRIGHT_BROWSERS_PATH    Custom Playwright browser cache.

Validation is in Chromium. This branch does not merge or deploy the redesign.
